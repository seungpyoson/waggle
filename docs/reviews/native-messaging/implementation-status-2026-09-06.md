## Invariant and production changes

Only the acquired broker owner may commit canonical state. A native message targets one exact enrollment incarnation; possession, dispatch disposition, and consumption are separate facts. Message transitions run through `messages.Store.Apply` inside one fenced owner transaction. The store never opens a database. SQLite foreign-key enforcement is enabled at the sole canonical connection constructor, so the reference constraints actually apply to every pooled connection.

The earlier ownership implementation remains: process-lifetime acquisition, transactional generation fencing, mandatory transaction capabilities for task writers, owner-controlled v2 endpoints, bounded admission/drain, and cleanup before ownership release. The shutdown fix uses the already-admitted service operation for disconnect cleanup; it does not reopen admission or suppress a failed task requeue.

This pass replaced name-addressed messages with canonical enrollments, conversations, messages, immutable attempts, append-only receipts, and one unique recipient barrier. Selection spends conversation budget and commits intent plus barrier atomically. Stop, expiry, disconnect and restart cannot erase provider possession or authorize a second attempt. Later messages expose the original blocking message ID. Retirement disables routing without claiming native withdrawal; reenrollment cannot bypass retained input in the same provider conversation.

The send path is now authenticated RPC to canonical enqueue. It returns storage evidence, never delivery success. Direct send rejects pending or disconnected targets. Explicit offline enqueue accepts an enrolled bound/disconnected recipient. Reply inherits the original recipient, correlation, deadline and budget; overrides fail. Inbox is read-only. One configured broker default assigns the deadline after idempotency lookup. Repeating an identical request ID preserves the stored deadline, even after expiry or a configuration change. Caller-supplied request IDs are supported; no automatic send retry exists.

The old machine runtime, adapter bootstrap, runtime commands, listener delivery, name-push reservations, replay acknowledgements, signal consumption and shell delivery implementation have been removed. The former inbox mark-seen mutation is absent. A source search finds one canonical `sql.Open`, in `internal/brokerstate/acquire.go`; that inventory is not behavioral proof.

Claude SessionStart enrollment is a bounded private RPC client. It reads the native session ID and socket endpoint and appends only an independently issued Waggle credential after successful enrollment. It never reads the native messaging token or prints enrollment credentials. The production connector currently rejects Claude enrollment explicitly because its native verification and submission driver is not implemented. Codex SessionStart enrollment and per-thread credential propagation are also not implemented.

The broker now runs one native scheduler through its required connector. Enrollment support and the configured endpoint are checked before storing a registration. Startup and live work enter the same bounded database scan; wakeups contain no messages and are only hints. Observation pages exclude terminal history and use a keyset cursor, also exposed by the read-only sessions command. Native observations can bind pending sessions without a tool call; unavailable observations retain the original pending deadline, and late observations cannot revive failed or retired enrollments.

Each scheduler batch remains inside one admitted owner operation across native observation, atomic selection/intent/barrier, submission, fenced receipt persistence and driver close. Bounded batches join all their native work before admission can drain. Drivers do not own queues, retry submissions, change permissions or select another endpoint. Cancellation of native I/O does not cancel persistence of observed evidence. The broker RPC tests now use this scheduler instead of manually inserting selection or binding evidence. Their execution remains blocked by the Unix socket restriction below.

The maintained Codex WebSocket implementation is connected to this broker path. The explicit startup input is `--codex-app-server <absolute socket>`; enrollment cannot supply an unregistered endpoint. The connector verifies the connected peer's kernel UID against the broker's effective user before HTTP upgrade or provider data. Darwin uses LOCAL_PEERCRED and Linux uses SO_PEERCRED; unavailable credentials fail, with no PID/path inference. Its single constructor performs Unix WebSocket upgrade, initialization, bounded framing and request correlation. Metadata probes require the exact loaded thread and an affirmative native direct-input field. Idle submission uses turn/start; busy submission uses turn/steer with the observed active-turn ID. A failed steer cannot switch to start. Only the broker-authored envelope is text input; the DTO contains no model, sandbox or approval override fields. Positive correlated native responses are recorded separately from consumption; a possibly written request without one remains uncertain. Native response bodies and close reasons are excluded from diagnostics.

Connections are scoped to observation or submission and their readers are joined at close. This fails to implement the approved retained thread subscription: the Codex driver never subscribes. The effects of connection closure on native turn retention, concurrent remote TUI operation, and delivery of approval requests to that TUI are **not confirmed**. This code does not establish the native guarantees required for M1 and must not be activated as a supported provider integration.

Installed instructions no longer invoke deleted bootstrap/listener commands or infer messaging identity from a name, PID or terminal. Installation reports file installation without promising native activation. Retirement removes only the exact Waggle-owned command from mixed hook entries and preserves unrelated hooks, permission settings and file modes. Truncated managed blocks fail without discarding user content. Old shell and PreToolUse strings remain only where needed to remove known installed artifacts; there is no operational legacy delivery path.

## Native evidence and exact limitations

### September 7: Codex subscription capability gap

**Invariant:** a broker may manage only the exact existing native conversation, retaining its subscription without reopening a stopped conversation or changing native policy. The per-project broker owns that lifecycle; the native driver must obtain the subscription through a supported provider operation. A database ownership capability cannot create a capability missing from the provider protocol.

**Current production path:** `cmd/start.go` constructs `native.Connector`; `broker.routeMessages` checks enrollment inputs; `broker.schedule` opens, probes and closes an observation connection before committing binding, then opens a separate connection for submission and closes it after recording the outcome. `codex.Connection.Probe` calls `thread/read`, and `Submit` calls `turn/start` or `turn/steer`. None acquires a thread subscription. The approved design at line 133 requires retaining one. Passing the existing transport fixtures does not verify this missing step.

The installed CLI reports `0.153.4`. Its generated `ClientRequest` schema has `thread/resume` and `thread/unsubscribe`, but no subscribe-only request; `ThreadResumeParams` has no loaded-only precondition. The official release tag `rust-v0.153.4` resolves to commit `3d2ee51ca2d5db578f328aa75e20aa22c0197c9a`. Direct inspection of that release source establishes:

- Initialization records a live connection; it does not attach that connection to existing threads. [ThreadStateManager::connection_initialized](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/thread_state.rs#L346)
- `thread/read` returns a view without subscription. [ThreadProcessor::thread_read_response_inner](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/thread_processor.rs#L2790)
- `turn/start` and `turn/steer` resolve an already loaded thread and submit input; their inspected handlers do not attach the requesting connection. [TurnProcessor::turn_start_inner](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/turn_processor.rs#L502), [turn_steer_inner](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/turn_processor.rs#L994)
- `thread/resume` first handles a running thread; when none is running it loads stored history and calls `resume_thread_with_history`, then attaches. Checking readiness beforehand cannot prevent a concurrent unload from entering this cold-resume branch. [ThreadProcessor::thread_resume_inner](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/request_processors/thread_processor.rs#L3572)
- The server attaches initialized connections when a thread is newly created. This does not attach a broker reconnecting to an existing thread and does not provide the required restart contract. [App Server thread-created handler](https://github.com/openai/codex/blob/3d2ee51ca2d5db578f328aa75e20aa22c0197c9a/codex-rs/app-server/src/lib.rs#L1148)

**Decision:** stop this implementation step. No probe-then-resume sequence, alternate submission path, connection registry, policy change or provider-source patch was added. The missing capability is an atomic subscription to the exact already loaded conversation that rejects an unloaded/closing target without reopening it. A provider operation with those semantics, or an explicit revision of the requirement, is needed before implementing attachment. Merely holding the current connection open would not acquire a subscription. The ordinary per-thread enrollment credential mechanism remains independently unconfirmed.

This is a source/schema finding, not a native execution result. No native conversation was created, resumed, enrolled or messaged during the investigation. No production code or approved design text changed. Source and schema digests are recorded in `implementation-verification-2026-09-06.json`. The existing syscall restrictions still prevent the real broker/native conformance run; unchanged failed commands were not repeated. M1 remains unapproved, and M2/M3 have not begun.
